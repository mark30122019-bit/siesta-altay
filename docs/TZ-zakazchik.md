# ТЗ от заказчика — «Алтай изнутри» / ООО «Сиеста Центр»

Дата фиксации: 11 сентября 2026  
Источник: сообщение заказчика (срочные правки + наполнение данными).

---

## 0. Контекст

На сайте сейчас опубликован контент-рыба под вёрстку (цены, локации, авторские отзывы).  
Базы **реальные**, с ними у заказчика рабочие отношения. Публиковать выдуманные факты от имени «Сиесты» **нельзя**.

Пример ошибки в рыбе: про базу «Воздух» написано, что шумно и играет рок-музыка; по факту — тихое место под ретриты, локация Усть-Сема (не Узнезя).

---

## 1. Срочно (до появления реальных данных)

| № | Требование | Детали |
|---|------------|--------|
| 1.1 | Закрыть сайт от поисковиков | `noindex` (сейчас `index, follow` — убрать) |
| 1.2 | Убрать телефон заказчика | Не показывать личный/рабочий телефон на сайте, пока контент не готов |

Цель: сайт не должен индексироваться и не должен выглядеть как официальная публикация недостоверных данных.

---

## 2. Данные по базам

Хранение: один источник — **`src/config/global.ts`** → `GLOBAL_CONFIG.objects`  
Схема: **`src/types/index.ts`** → `BaseObject`

Задача по данным: **не заводить параллельный `objects.json` в проде**.  
Черновик заказчика (если придёт JSON/таблицей) **вливается в существующие объекты** в `global.ts`: поля заказчика **заменяют рыбу**, служебные поля сайта **оставляем/дозаполняем сами**.

### 2.1 От заказчика (контент / факты — не выдумывать)

| Поле в `BaseObject` | Что именно |
|---------------------|------------|
| `name`, `type` | Название и тип базы |
| `location.*` | Район, населённый пункт, координаты, км от ГА/Нск, дорога, зимний доступ |
| `tour.url` | Ссылка на 3D-тур |
| `tour.scenes_count` | Число сцен в туре |
| `capacity.*` | Вместимость min/max, число домиков/юнитов |
| `amenities.*` | Удобства (баня, бассейн, wifi, кухня, отопление, парковка, у воды, еда, животные, круглый год) |
| `author.verdict` | Авторский вердикт |
| `author.good_for` | Кому подойдёт (тексты) |
| `author.not_for` | Кому не подойдёт (тексты) |
| `author.honest_note` | «Честно от автора» (если дал) |
| `suitability.*.note` | Пояснения по аудиториям, если заказчик их дал вместо/вместе с `good_for` / `not_for` |

Правило: тексты и факты заказчика **вставлять as-is**, не «улучшать» и не дописывать отзывы от имени Сиесты.

### 2.2 От нас (сайт / витрина / техника)

| Поле в `BaseObject` | Что именно |
|---------------------|------------|
| `slug` | URL-ключ страницы (`/base/[slug]`), стабильный, латиница |
| `verification`, `verification_date` | Статус съёмки/проверки для витрины |
| `consent` | Служебное: согласие базы на публикацию |
| `tour.preview` | Превью тура (путь в `public/`), пока скрин из тура |
| `photos[]` | Галерея: пока временные кадры из тура; потом — реальные фото заказчика |
| `price?` | Опционально; **сейчас не публикуем** (см. §3) |
| `suitability.*.fit` | У заказчика уже `boolean \| null` — берём как есть для фильтров «для кого» |
| `booking.*` | Правила заявки на сайте (мин. ночи, предоплата) — наши, пока заказчик не уточнит иное |
| `seo.*` | title / description / og_image под выдачу (на период `noindex` всё равно готовим) |
| `status` | `draft` — скрыт; `ready_for_review` / `published` — на витрине |
| `updated_at` | Дата обновления записи |

Плюс вне объекта базы (тоже наше): `filters`, `manifest`, `promoTour`, `testimonials`, UI-тексты в `uiConfig.ts`, форма заявки, API → Telegram.

### 2.3 Публикация (6 + 3)

| Действие | Описание |
|----------|----------|
| Показать | 6 баз: поля заказчика скопированы в `global.ts` as-is (`ready_for_review`) |
| Скрыть | 3 базы: `status: "draft"` (каталог / главная / sitemap не отдают) |

**Статус:** объекты заказчика лежат в `src/config/global.ts` (без JS-маппера). Для сверки — `data/objects.customer.json`.  
На витрине всё, кроме `draft`. Цены только если `price.publish === true` и числовой `from`.

---

## 3. Цены

- Поле `price` у объекта **опциональное**.
- Нет `price` → на карточках цены нет; на странице базы — пояснение про уточнение при заявке.
- Есть `price` → показ как раньше (карточки, блок «Сколько стоит», фильтр по цене, карта, JSON-LD).
- Сейчас в данных цены сняты (не публикуем), UI без цен.

## 4. Фотографии

- Съёмки и отбор фото заказчик пока не делал.
- **Временно:** скриншоты из 3D-туров как обложки/галерея.
- Когда появятся нормальные фото — заменить.

---

## 5. 3D-тур на странице базы

| Сейчас | Нужно |
|--------|--------|
| Тур зажат в слот под фото | Оставить превью/слот, но не считать это единственным способом открытия |
| Грузится сразу | **Ленивая загрузка по клику** — не тянуть первый экран |
| Фулскрин только внутри плеера | Отдельная кнопка **«Открыть на весь экран»** **вне** рамки тура — не все находят встроенный fullscreen |

---

## 6. Приоритеты работ

1. **P0 / срочно:** `noindex` + убрать телефон.  
2. **P1:** в `global.ts` заменить рыбу полями заказчика (§2.1), служебное оставить (§2.2); 6 published / 3 draft.  
3. **P2:** временные скриншоты из туров.  
4. **P3:** тур — load on click + кнопка «Открыть на весь экран» снаружи.

---

## 7. Критерии приёмки (чеклист)

- [x] В `robots` / meta: `noindex` (сайт не для индексации).
- [x] Телефон заказчика нигде на страницах не отображается.
- [x] У 6 баз в `global.ts` стоят поля заказчика (§2.1), без выдуманных отзывов/локаций.
- [x] Три незаполненные базы в `draft` (каталог, главная, sitemap).
- [x] Служебные поля (§2.2: slug, seo, status, preview/photos) не сломаны после вставки.
- [x] Цены нигде не показываются; вместо цифр — пояснение, что стоимость уточняется при заявке.
- [ ] Фото: временные кадры из туров (если реальных фото ещё нет).
- [ ] Тур не грузится до клика пользователя.
- [ ] Есть кнопка «Открыть на весь экран» вне iframe/рамки тура.

## 8. Вне скоупа этого ТЗ

- Сбор и отбор финальных фото.
- Актуализация цен и акций.
- Возврат скрытых баз (отдельная задача, когда заказчик даст данные).
- Снятие `noindex` после готовности контента (отдельное явное решение заказчика).
