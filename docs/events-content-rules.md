# Правила раздела «Мероприятия» / «Свадьбы»

Документ для наполнения заказчиком. Источник правды в коде: `src/lib/object-events.ts`, поле `events` у объекта в `src/config/global.ts`.

---

## 1. Когда объект попадает в раздел

Объект должен быть опубликован (`status` не `draft`).

### Мероприятия (`/corporate`, `/events/[slug]`)

| `events.suitable` | Поведение |
|-------------------|-----------|
| `false` | Скрыт из раздела |
| `true` | В разделе (даже если залы ещё пустые) |
| `null` / не задан | В разделе, если есть **сигнал** данных (см. ниже) |

**Сигнал для витрины** (достаточно одного):

- есть хотя бы один зал в `events.venues`;
- или `buyout.available === true`;
- или указаны спальные места (`beds_total` / `beds_single_occupancy`);
- или есть активности / безнал / работа с юрлицом / заметка по проживанию.

### Свадьбы (`/weddings`, `/weddings/[slug]`)

- `suitable === false` → скрыт;
- иначе: есть **wedding-сигнал** (церемония, план на дождь, комната невесты, свои подрядчики, эксклюзивная дата, фотозоны, комендантский час);
- пока wedding почти пустой — MVP показывает те же объекты, что и «Мероприятия» (по events-сигналу).

### SEO / sitemap

В sitemap и в индекс попадают только **заполненные** карточки:

- Мероприятия: `suitable === true` **или** есть хотя бы один зал в `venues`;
- Свадьбы: есть wedding-сигнал **или** выполнен критерий заполненности мероприятий.

Карточки только с «безналом» и без залов могут быть на витрине, но **не** в sitemap (`noindex`).

## 2. Корзины вместимости: «до 15» / «до 40» / «100+»

Фильтр на витрине — **взаимоисключающие** корзины. Число для сравнения — `getEventsCapacityMax` (одна оценка на объект).

### Как считается число гостей (приоритет, первое ненулевое)

1. **Максимум по залам** — по всем `venues[].capacity` берётся наибольшее из: theatre / banquet / buffet / classroom  
2. Иначе `sleeping.beds_total`  
3. Иначе `sleeping.beds_single_occupancy`  
4. Иначе `buyout.min_guests`  
5. Иначе `null` — на карточке «Уточняется», **в корзины фильтр не попадает** (виден только при «Все»)

### Границы корзин

| Корзина | Условие |
|---------|---------|
| **до 15** | вместимость ≤ 15 |
| **до 40** | 15 < вместимость ≤ 40 |
| **100+** | вместимость ≥ 100 |

Диапазон **41–99** сейчас **не покрыт** отдельной корзиной: объект виден при «Все», но не при выборе «до 40» или «100+». Если нужна корзина «до 100» — отдельное решение по продукту.

### Что писать заказчику в данные

- Для фильтра важнее всего **вместимость залов** (хотя бы одна рассадка с числом).
- Спальные места и выкуп — запасной источник, если залов ещё нет.
- Не ставить «красивые» числа без согласования с базой: на витрине это факты для организатора.

---

## 3. Что показывать как «Уточняется»

Любое поле `null` / пустая строка в блоках events (залы, выкуп, кейтеринг, техника, логистика, сезон, юрлицо, свадьба) на странице объекта отображается как **«Уточняется»**.  
Пустой блок залов целиком → текст: данные уточняем с базой.

Правило контента: лучше `null` + «Уточняется», чем выдуманная цифра.

---

## 4. Чеклист перед публикацией в раздел

- [ ] `status` не `draft`
- [ ] `events.suitable` = `true` (или осознанный MVP-сигнал)
- [ ] Хотя бы один зал с площадью и/или рассадкой — чтобы попасть в sitemap
- [ ] Вместимость зала заполнена, если объект должен находиться фильтром «до 15 / до 40 / 100+»
- [ ] Для свадеб: заполнены релевантные поля `events.wedding`
- [ ] Тексты и цифры согласованы с базой, без рыбы
